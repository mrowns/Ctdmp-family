# Product requirements

Source: owner-supplied CTDMP Connect Comprehensive Product and Engineering Specification v1.0, 23 October 2026, sections 0–35 in the project conversation. The original Downloads files and separate project bible are not present on the VPS and have not been independently inspected.

The first milestone is Phase 0 foundation plus Phase 1 simulated livestream notification, deliberate personal joining, scoped history and same-link stream recovery. Full delivery includes WhatsApp, responsive web/PWA, scoped administration, moderated community, directory, real-human referrals, and later Expo Android/iOS. Later features are not represented as implemented.

Core invariants: immutable session identity across replacement; approved sources only; candidates never imply live; one logical initial notification per member/program/purpose/channel/version; HEAD/GET never create engagement; one live action per member/program; live and replay actions separate; destination resolved at protected POST; opt-out checked at dispatch; atomic money reservations; database is truth; mock results never imply live delivery or attendance.

No pastoral AI, clergy impersonation, spiritual assessment, faith ranking, WhatsApp scraping, inferred identity, or fabricated church/source verification. Public broadcasts remain reachable without compulsory analytics. Private link actions are not watch-time or attendance evidence.

Owner has superseded original local-only execution restriction and authorized VPS development. Public exposure, real sending, paid integration activation and real member publication remain unapproved.

Phase 1 acceptance follows source section 29: actual database/API/worker/frontend demonstration, permission denials, Stream A→B, duplicate/race safeguards, policy failures and sanitized evidence. Backend tests alone do not pass the gate.

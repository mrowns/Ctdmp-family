# Implementation plan

1. Foundation: clean VPS reconnaissance; pnpm/TS; validated fail-closed config; Docker PostgreSQL/Redis; migration locking/checksums; fictional seed; shared domain and permission vocabulary; safe source control and CI.
2. Backend slice: mock observation/recovery; outbox/dedup; encrypted personal payload; protected resolver; scoped histories; consent/budget gates; signed durable inbox; worker restart proof.
3. Member frontend and scoped control room: Next.js/Tailwind, same-origin API routing, accessible low-data joining/history/preferences and evidence/status screens. Add protected admin review commands with recent authentication and revisions.
4. Complete first acceptance: secure fixture session workflow, all section 29 scenarios, browser/no-JS checks, screenshot evidence, webhook challenge/real contract adapter, audit completeness, config and privacy cleanup. Do not label Phase 1 complete until those pass.
5. Public identity and Meta pilot preparation: passkeys/recovery/linking, grants governance, real adapter validation, template/cost approvals and explicit controlled sending approval.
6. Later phases: community, directory/human routing, privacy rights; native apps; approved production operations and release.

Owner decisions for local mock implementation are not blockers. Ask for official channels/schedule, branding authority, real account/budget and policies only when activating the dependent capability.
